# 安伴 · 家属关爱端与床侧演示

React 前端包含家属端和床侧语音演示两个入口，两者均已通过 HTTP 接口接入独立运行的护理床 Agent。前端不包含 Agent 进程，也不保存后端密钥。

## 页面结构

- 首页：有来源的今日近况、AI 摘要、新留言与护理事项概览。
- 联系：语音留言、AI 摘要和通话记录组成的统一时间线。
- 我的：关爱档案、Agent 偏好、设备与隐私设置。
- 护理事项：查看、新增、编辑、删除、启用或停用护理计划。
- 床侧语音演示：左侧保持语音入口，右侧按当前请求切换身体舒适、照护协同、家人联系与日常服务结果；待机时展示“今日床侧”，而不是功能清单。

麦克风联系入口仅在首页和联系页显示，不在“我的”页面显示。App 不提供远程床体运动控制。

## 本地运行

推荐从项目根目录一键启动前端和 Agent：

```powershell
npm run dev
```

首次运行前，在项目根目录执行 `npm --prefix app install`。如只启动前端，可执行 `npm --prefix app run dev`，但需另行启动 Agent，否则页面会显示未连接状态。

启动后可访问：

- 家属端：`http://127.0.0.1:5173/`
- 床侧语音演示：`http://127.0.0.1:5173/voice-demo.html`

床侧演示建议使用 Chrome 或 Edge，并优先以 `1920×1080` 投屏；`1440×900` 也经过无滚动适配。点击麦克风或按空格键即可开始说话；焦点位于输入框或按钮时不会误触快捷键。浏览器不支持或未授权时，文字输入仍然可用。“演示指南”示例只填入输入框，便于讲解者确认后再发送。

结果页沿用与待机页相同的暖白、灰绿和细边框视觉系统：床体只显示姿势与数值，照护、通话、留言、媒体和应急分别显示真实业务状态；取消受保护动作后会明确提示床体没有执行调整。页面不展示模型推理步骤、发光球或床体姿态插画。

## 数据流

- 开发环境使用相对路径 `/api/v1/*`，由 Vite 代理到 `http://127.0.0.1:8765`。
- 家属端从 Agent 加载设备状态、护理事项、留言与通话，新增、编辑、删除和启停操作都会写回 Agent。
- 床侧页面调用 `/api/v1/bedside/messages`，请求来源由后端固定为床侧语音，前端不能伪造来源权限。
- 每次话术只接收后端返回的一次结构化执行结果；前端不直接读取 Prompt 或能力目录，也不在浏览器中保存服务端密钥。
- 床侧页面为每次加载生成新的 `voice-session-*` 标识，只在 React 内存中保留最近 8 轮对话，并以最多 16 条 `user`/`assistant` 消息作为理解上下文；刷新即清空，不写入浏览器存储。
- 如需连接其他 Agent 地址，可设置 `VITE_AGENT_BASE_URL`；不要将 `GLM_API_KEY` 或其他服务端密钥放入 Vite 环境变量。

## 测试与构建

```powershell
npm run test:run
npm run build
```

生产构建输出在 `dist/`，同时包含 `index.html` 和 `voice-demo.html`。部署时可将该目录发布到任意静态网站托管服务。

当前 Agent 数据保存在内存中，服务重启后恢复为演示种子数据。床控硬件、真实电话、生产联系人、天气、媒体和外部护理系统均未接入；页面展示的是确定性模拟结果。

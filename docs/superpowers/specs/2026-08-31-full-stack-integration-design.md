# 护理床前后端完整联调设计

## 目标

将 `app/` 中的家属端与床侧语音演示同时接入 `agent/`，由 Agent 成为业务状态与自然语言执行结果的唯一来源。开发者在项目根目录执行一条命令即可同时启动 Python Agent 和 Vite 前端。

## 约束

- Agent 保持独立 Python 进程，不嵌入浏览器。
- `GLM_API_KEY` 仅由 `agent/.env` 加载，不进入前端环境变量或构建产物。
- 家属端不得远程控制床体；床侧请求由独立接口固定标记为 `voice` 来源。
- APP 与 Agent 只通过 `agent/contracts/openapi.json` 描述的 HTTP 接口通信。
- 本阶段继续使用内存存储；Agent 重启后恢复演示种子数据。
- 不连接真实床控、电机、电话或音频服务。

## 总体架构

根目录的 Node 启动器负责拉起两个子进程：Agent 在 `127.0.0.1:8765` 监听，Vite 在 `127.0.0.1:5173` 监听。启动器先等待 Agent 健康检查成功，再启动前端；任一子进程异常退出时清理另一方并返回非零退出码。

Vite 将 `/api/*` 代理到 Agent，因此开发态前端使用相对地址，不依赖跨域配置。生产态允许通过 `VITE_AGENT_BASE_URL` 指向独立部署的 Agent。

## 后端接口

### 服务与读取

- `GET /api/v1/health`：统一 API 前缀下的健康检查，同时保留 `/health` 兼容入口。
- `GET /api/v1/state`：床体权威状态。
- `GET /api/v1/demo/overview`：照护、留言、通话与日常生活总览。
- `GET /api/v1/reminders`：护理事项列表。

### 家属端结构化操作

- `POST /api/v1/reminders`：新增护理事项。
- `PATCH /api/v1/reminders/{reminder_id}`：编辑标题、时间、说明、状态或启用状态。
- `DELETE /api/v1/reminders/{reminder_id}`：删除护理事项。
- `POST /api/v1/voice-messages`：写入家属发送的留言记录。
- `POST /api/v1/calls`：开始模拟通话。
- `PATCH /api/v1/calls/{call_id}`：结束模拟通话。

这些按钮操作走确定性的业务接口，不调用大模型。

### 自然语言操作

- `POST /api/v1/agent/messages`：家属端自然语言入口，后端固定使用 `EventSource.APP`，床控意图继续返回 `403`。
- `POST /api/v1/bedside/messages`：床侧自然语言入口，后端固定使用 `EventSource.VOICE`。

请求不接受可伪造的 `source` 字段。响应沿用 `AgentResult`，并在 `data.interpretation` 中增加经后端校验后的意图、动作、目标、参数和置信度，供床侧“Agent 如何理解”面板展示。

## 床侧确认流程

大幅床体动作和复位动作不能在首次自然语言识别后立即执行。Agent 将待执行意图保存到当前 `actor_id` 的会话上下文，并返回 `needs_confirmation`。后续“确认”执行该待办，“取消”清除待办；“停止”始终立即执行并清除待办。

床侧页面只负责语音转文字、提交文本、显示结果和语音播报。原有本地意图引擎不再决定执行结果，避免前后端产生两套互相冲突的状态。

## 家属端数据流

页面启动时并行读取健康状态、业务总览、床体状态和护理事项。后端预置与当前页面相符的护理事项、护理记录、留言和通话演示数据，前端将 API 数据转换为现有 `CareTask`、`TimelineItem` 和首页动态结构。

新增、编辑、启停、重置与删除护理事项均先请求 Agent，成功后刷新数据。留言发送、通话开始与结束同样由 Agent 写入内存状态，再更新界面；失败时不在浏览器中伪造成功记录。

床侧执行提醒、护理记录、留言或通话后，家属端重新加载或刷新数据即可看到相同 Agent 状态。

## 前端模块边界

- `src/api/types.ts`：公开接口对应的 TypeScript 类型。
- `src/api/client.ts`：超时、JSON 解析、错误归一化和具体 API 方法。
- `src/api/adapters.ts`：Agent DTO 到现有页面模型的纯函数转换。
- `App.tsx`：家属端请求编排和页面级状态，不包含 DTO 转换细节。
- `VoiceDemoApp.tsx`：语音识别与交互状态，不包含本地执行逻辑。

独立请求并行发起，避免加载瀑布。派生值在渲染期间计算，不额外复制到 React 状态。

## 错误与状态

- 启动失败：根启动器打印 Python、端口或健康检查错误并停止全部子进程。
- Agent 未连接：页面显示离线状态，写操作禁用或失败提示，不显示“已同步”。
- 请求处理中：提交按钮禁用，床侧显示“正在理解”。
- 业务拒绝或需澄清：解析结构化 `AgentResult` 并展示后端原始中文消息。
- 模型未配置、超时或不可用：分别展示可读错误；不回退到关键词执行。
- 语音识别不可用：继续保留文字输入，与 Agent 连接状态互不混淆。

## 验证

- 后端单元与接口测试覆盖床侧来源、家属床控拒绝、确认流程、护理事项 CRUD、留言和通话写入。
- 前端单元测试覆盖 API 错误归一化、DTO 转换和日期/状态映射。
- React 组件测试覆盖家属端加载与同步、离线失败，以及床侧真实 Agent 响应与确认。
- 完整运行 Python 测试、Vitest、TypeScript/Vite 构建。
- 使用浏览器验证家属端和床侧页面、控制台错误、请求流及一条完整跨页面状态链路。

## 非目标

- 数据库、账号认证、设备证书和云部署。
- 真实音频上传、实时音视频通话。
- 真实护理床硬件控制。
- 将床侧授权方案直接用于生产环境；生产环境仍需设备身份认证。

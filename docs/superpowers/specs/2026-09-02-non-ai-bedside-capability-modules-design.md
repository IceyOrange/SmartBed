# 去 AI 化床侧界面与能力模块化设计

## 目标

在不改变演示核心路径的前提下，同时完成两项升级：

1. 将床侧语音页面从“通用 AI 控制台”重构为可信、克制、生活化的高端护理设备界面。
2. 将自然语言后端整理为“能力目录驱动的一次识别 + 本地校验 + 独立能力处理器 + 可替换执行端口”，提高识别稳定性并为真实系统接入预留清晰边界。

本阶段仍是浏览器投屏演示，不建设长期记忆、数据库、声纹识别、多步骤自主规划或可让模型直接调用设备的重型 Agent。

## 已确认的产品原则

- 用户通过点击语音键或按空格键开始、结束语音输入；文字输入作为稳定兜底。
- 每次打开或刷新页面都创建新的临时会话，最多保留最近 8 轮对话，不写入数据库或浏览器长期存储。
- 模型只负责把最后一条用户表达识别成受约束的结构化意图；执行、安全、确认和状态更新全部在本地确定性代码中完成。
- 实体停止、安全限制、大幅床体动作确认和 APP 禁止远程床控等边界保持不变。
- HTTP 接口、前端使用的 `AgentResultDto` 结构和现有四个产品领域保持兼容。
- 演示中的床控、通话、天气、媒体、护理系统仍是模拟实现，但代码边界应允许未来单独替换真实适配器。

### 视觉定位

页面应像一块长期放置在卧室中的高端护理设备屏幕，而不是聊天机器人、模型演示台或 SaaS 仪表盘。

- 使用暖白、灰绿、深墨绿和少量护理警示红。
- 主要容器采用低阴影、细边框和中等圆角；避免漂浮卡片堆叠。
- 标题可使用现有中文字体中的宋体风格作为生活化层次，正文和控件继续使用可读性高的无衬线字体。
- 不使用发光球体、渐变光晕、星芒、机器人形象、模型思考链或“AI 正在推理”等表达。
- 功能通过今日状态、下一项照护、家人留言、天气和床体数据自然呈现，不展示生硬的能力清单墙。

### 页面结构

继续保留双舞台，但由两个连续设备面板组成：

1. **左侧语音区**
   - 欢迎语和一句明确说明。
   - 横向实体按键式语音控制条，包含麦克风按键、主文案和空格键提示。
   - 简洁的文字输入行。
   - 最近使用记录，来源仍是本页面临时会话。
   - “怎么说”打开现有演示指南。

2. **右侧今日床侧区**
   - 当前床体姿势与靠背、腿托、床高数据。
   - 下一项照护、家人留言和天气三条生活信息。
   - 午休姿势建议作为轻提示，不自动执行。
   - 底部连续状态栏呈现身体舒适、照护协同、家人联系和护理呼叫。

### 语音状态

语音入口保留同一 DOM 结构和可访问性语义，但视觉反馈改为设备状态，而不是 AI 过程：

- 待机：`点击开始说话`。
- 准备：`正在打开麦克风`。
- 聆听：`正在听`，控制条使用稳定边框和轻微电平反馈。
- 处理中：只显示 `正在处理`，不展示“已听清 / 理解需要 / 安全处理”等内部步骤。
- 完成：显示用户原话和简短结果，右侧切换到对应业务结果页。
- 失败：保留原话、明确错误和重新发送按钮。

### 业务结果页

通话、留言、应急、提醒、床控、天气、媒体等结果继续使用现有数据映射和按钮行为，但统一为设备面板语言：

- 减少居中空舞台和装饰性图标。
- 优先展示状态、对象、时间和可执行按钮。
- 床体结果只显示数值和状态，不绘制护理床姿态插画。
- 危险状态只在应急场景使用克制的警示红。
- 确认和取消应明确显示“将执行什么”和“取消后未执行”。

### 响应式和可访问性

- 主要验收尺寸为 1920×1080 和 1440×900，两个尺寸均不得出现页面滚动、裁切或文字重叠。
- 窄屏仍允许上下排列，但不以手机端为本阶段重点。
- 保留空格键规则、按钮可聚焦、指南焦点锁定、Escape 关闭、ARIA live 状态和低动态模式。

## 后端总体架构

### 请求链路

自然语言请求保持单次模型调用：

```text
用户文本 + 最近对话
  → 能力目录生成的系统提示词
  → GLM 返回单个 JSON 对象
  → JSON 解码
  → 意图契约校验与归一化
  → 会话上下文补全
  → 来源与安全策略
  → 独立能力处理器
  → 可替换执行端口
  → ExecutionResult
```

模型不能选择任意函数名、不能直接调用工具、不能产生机械参数之外的自由执行指令，也不能绕过本地确认和权限策略。

### 能力目录

新增一个中心化能力目录，作为以下内容的唯一事实来源：

- `kind`、`action`、合法 target、参数字段和参数类型。
- 必填参数和缺失时的澄清文案。
- 产品领域、用户可见名称和执行安全等级。
- Prompt 中使用的能力说明、正例和关键反例。
- 对应能力处理器的注册键。

能力目录不得包含执行服务实例，也不负责副作用。它是不可变描述数据，可由 Prompt 构建器和意图校验器共同读取，避免提示词与 Python 校验规则漂移。

### 模型提示词

系统提示词由稳定的基础规则和能力目录生成，结构固定为：

1. 角色与单一职责。
2. 安全优先级。
3. 输出 JSON 契约。
4. 支持能力及每项参数。
5. 冲突判定规则。
6. 正例和反例。
7. 上下文使用规则。

重点判定规则：

- `stop` 和明确求助优先于普通床控或陪聊。
- “把床全部放平”“调到睡眠姿势”识别为 `bed_scene/set_scene/sleep`。
- “记一下我吃过药了”是护理记录；“记一下眼镜在抽屉里”是生活记事。
- “听听女儿的留言”是留言播放；“播放一段京剧”是媒体播放。
- “给女儿说晚点回电话”是非实时留言；“给女儿打电话”是实时通话。
- “我想女儿了”不自动拨号，可识别为陪聊或未知。
- 询问天气、今日事项和纪念日是可执行查询；`should_execute=true` 表示允许本地处理该受支持请求，不表示模型已执行。
- 否定、拒绝、假设、转述、功能讨论、信息不足、医疗诊断、用药调整和不支持能力必须不执行。
- 历史消息只用于指代和连续表达；只有最后一条用户消息可触发动作。

输出仍为一个 JSON 对象，保持字段：`kind`、`target`、`action`、`parameters`、`confidence`、`negated`、`should_execute`、`utterance_type`。轻量陪聊的简短非医疗回复继续放在 `parameters.reply`，不增加第二次模型调用。

### 模型解释器拆分

将当前 `AiIntentInterpreter` 中的职责拆成三个可测试单元：

- `prompting.py`：从能力目录生成系统提示词。
- `intent_contract.py`：解码、字段校验、参数过滤、置信度和执行意愿处理。
- `model_interpreter.py`：组织历史消息、调用模型并把错误转换为 `IntentInterpretationError`。

`AiIntentInterpreter` 的公开构造和 `interpret()` 接口保持兼容。

### 能力处理器

用细粒度处理器替代一个领域类中的长分支。每个处理器只实现一个明确能力，并实现统一协议：

```python
class CapabilityHandler(Protocol):
    capability_id: str
    intent_kind: IntentKind

    def can_handle(self, intent: Intent) -> bool: ...
    def execute(self, intent: Intent, actor_id: str) -> ExecutionResult: ...
```

第一阶段处理器如下：

- 床体：微调、情景姿势、停止。
- 照护：提醒创建、护理记录创建、护理待办创建、应急呼叫。
- 家人：实时通话、留言播放/发送、纪念日查询/祝福。
- 日常：今日事项、天气、生活记事、轻量陪聊、媒体播放、日期时间。

`SkillRegistry` 保持对编排器的现有 `find(intent)` 接口，但内部注册对象改为细粒度处理器。为了兼容现有代码，可保留 `AgentSkill` 名称作为协议别名，不保留领域类作为额外路由层。

### 执行端口与模拟适配器

为可能替换真实系统的资源定义窄接口：

- `BedControlPort`
- `ReminderPort`
- `CareRecordPort`
- `CareTodoPort`
- `NotificationPort`
- `CallPort`
- `VoiceMessagePort`
- `AnniversaryPort`
- `WeatherPort`
- `NotePort`
- `MediaPort`

现有内存类继续作为默认实现，不增加 SQL。接口返回现有字典结构或现有数据类序列化结果，避免扩大 HTTP 契约变更。

服务状态应贴近真实生命周期：

- 通话：`calling` → `connected`/`ended`，本阶段界面仍只模拟发起和结束。
- 留言：`unread` → `playing`/`played`。
- 媒体：`idle` → `playing` → `paused`/`stopped`，本阶段至少保留播放状态。
- 应急呼叫：高优先级通话与紧急通知同时生成。
- 提醒、记录、待办继续有独立标识、创建者、时间和状态。

## 错误、安全与兼容

- 模型缺失、超时、网络错误、非法 JSON、非法枚举、低置信度都不得执行任何动作。
- 非法或多余参数由契约校验器丢弃；必填字段缺失则保留合法意图并由能力处理器返回具体澄清，而不是猜值。
- 床体动作仍经过 `AgentAccessPolicy` 和 `DeterministicBedController`。
- 大幅微调和所有情景姿势仍需二次确认；取消必须清除待确认动作。
- `/api/v1/agent/messages`、`/api/v1/bedside/messages`、健康检查、状态和总览接口保持路径与响应外形兼容。
- 前端不得读取能力目录内部实现，只消费既有 API 结果。

## 测试策略

### Prompt 与意图契约

- 快照式断言提示词包含全部能力、JSON 字段、安全规则和关键冲突案例。
- 表驱动测试覆盖支持能力、非法动作、非法 target、参数过滤、必填参数缺失、低置信度、否定、转述和查询。
- 真实 GLM 冒烟测试使用本地密钥，覆盖床体睡眠姿势、护理记录/生活记事、通话/留言、媒体、应急和拒绝场景；不纳入离线单元测试硬依赖。

### 能力处理器

- 每个处理器至少有成功、缺字段和底层空结果测试。
- 注册表测试保证每个能力只匹配一个处理器，未知意图不匹配。
- 端口使用内存实现做行为测试，保持现有 API 测试通过。

### 前端

- 保留现有语音、空格键、指南、失败重试、临时上下文和安全确认测试。
- 新增对“无处理步骤文案”“横向语音控制”“今日床侧关键信息”和取消未执行状态的测试。
- 生产构建后在 1920×1080、1440×900 验证待机、聆听、处理、结果、错误、指南和确认状态。
- 浏览器控制台不得有相关错误或警告，页面不得产生非预期滚动。

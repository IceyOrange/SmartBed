# 智能护理床软件 Demo

该项目已将家属端和床侧语音演示同时接入护理床 Agent：

- `agent/`：独立运行的 Python 服务，负责状态、护理事项、留言、通话、自然语言理解和安全确认。
- `app/`：React 前端，包含家属端和床侧语音演示两个入口。
- `scripts/dev.mjs`：先启动并检查 Agent，再启动前端；任一进程退出时会同步关闭另一方。

Agent 不嵌入前端页面。前端只通过公开 HTTP 接口访问 Agent，开发环境由 Vite 将 `/api` 代理到 `http://127.0.0.1:8765`。

## 演示能力

| 场景 | 可用能力 |
|---|---|
| 身体舒适 | 靠背、腿托和床高微调，吃饭/看电视/睡眠姿势，停止与复位 |
| 照护协同 | 护理提醒、护理记录、护理待办、应急呼叫 |
| 家人联系 | 实时通话、非实时留言、生日与纪念日祝福 |
| 日常服务 | 今日事项、天气、生活记事、轻量陪聊、内容点播 |

每句话只调用一次 GLM。模型负责把用户原话整理成受约束的结构化意图，不直接调用设备；后端随后执行本地契约校验、安全策略和对应能力处理器。床控、通话、提醒、记录、天气和媒体都通过独立端口连接当前的内存模拟实现，后续可逐项替换真实系统。

## 环境要求

- Python 3.12 或更高版本
- Node.js 和 npm
- Windows 中文语音识别器（床侧本机语音输入使用；当前电脑已安装）

首次运行先安装前端依赖：

```powershell
npm --prefix app install
```

如需体验自然语言理解和床侧语音命令，请复制 `agent/.env.example` 为 `agent/.env`，并填写 `GLM_API_KEY`。未配置密钥时，结构化的状态、护理事项、留言和通话接口仍可使用，自然语言请求会返回未配置提示且不会执行动作。

## 一键启动

在项目根目录运行：

```powershell
npm run dev
```

启动器会同时运行两个独立进程：

- 家属端：`http://127.0.0.1:5173/`
- 床侧语音演示：`http://127.0.0.1:5173/voice-demo.html`
- Agent 健康检查：`http://127.0.0.1:8765/api/v1/health`

按 `Ctrl+C` 会同时停止前端和 Agent。

床侧页可点击麦克风或按空格键开始说话，再次点击或按空格键可结束浏览器语音输入。页面会优先使用 Agent 进程中的 Windows 本机中文识别，最长监听约 8 秒，音频不上传；本机识别器不可用时才回退到浏览器语音识别。焦点位于输入框、按钮等可编辑控件时，空格键不会触发语音快捷键。请在 Windows“麦克风隐私设置”中允许桌面应用访问麦克风，并将要使用的设备设为系统默认输入设备。

页面采用双舞台布局：左侧始终保留语音与文字入口，右侧待机时展示“今日床侧”，执行后切换为对应业务结果。床体结果只显示姿势、数值和安全状态，不绘制床体；确认、取消、通话、留言、媒体和应急均有独立反馈。建议投屏使用 `1920×1080`，同时适配 `1440×900`。

文字输入是稳定兜底入口；“演示指南”中的话术只会填入输入框，不会自动执行。适合现场演示的示例包括：

- 身体舒适：`把靠背升高一点`、`调到吃饭姿势`、`调到睡眠姿势`、`马上停下`。
- 照护协同：`十分钟后提醒我喝水`、`记一下我吃过药了`、`今天还有什么护理事项`、`救命，快叫护理员`。
- 家人联系：`给女儿打电话`、`给女儿留言说我晚点回电话`、`给孙女送生日祝福`。
- 日常服务：`今天有什么安排`、`今天天气怎么样`、`记一下眼镜在抽屉里`、`播放一段京剧`。

床侧页只在当前页面内保留最近 8 轮对话，用于理解“再高一点”“继续播放”等连续表达。刷新页面会生成新的临时会话并清空这段上下文，不使用数据库、`localStorage`、声纹或长期记忆。

## 安全边界

- 家属端不能远程控制床体，即使通过自然语言提出也会被 Agent 拒绝。
- 床侧的大幅床体动作需要二次确认；取消、停止会清除待确认动作。
- 本机语音接口只接受受信任的本地演示页来源，并要求启动时生成的随机会话令牌，其他网页不能直接触发麦克风。
- 当前床控硬件、实时通话、媒体、天气和外部护理系统仍为演示实现，不会驱动真实设备。
- 页面中的联系人、护理记录、提醒结果和服务状态均用于产品演示，不应作为真实医疗或应急处置依据。
